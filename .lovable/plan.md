# ログイン認証と個別お気に入りの修正

## 変更内容

1. **標準のメール・パスワード認証に統一**
   - ログイン失敗時に、入力されたパスワードでアカウントを自動作成する `ensureAccount` フォールバックを削除します。
   - ログイン画面は、バックエンドの Auth に登録されているメールアドレスとパスワードを `signInWithPassword()` でそのまま照合します。
   - 認証失敗時は「メールアドレスまたはパスワードが違います」と表示し、内部エラーの詳細は利用者へ漏らしません。
   - 認証後は従来どおり `members.user_id` と `is_active` で利用可否を判定します。

2. **お気に入りをログインユーザー別に保存**
   - ユーザーIDに紐づく `saved_items` テーブルを追加します。
   - 各ユーザーが自分のお気に入りだけを閲覧・追加・削除できるよう、行レベルのアクセス制御を設定します。
   - トップページとお気に入りページを、共通のブラウザ保存ではなくバックエンド保存へ切り替えます。
   - ログアウト時に前ユーザーのお気に入りが画面やキャッシュに残らないようにします。

3. **既存お気に入りの移行**
   - 現在のブラウザに残っている共有形式のお気に入りは、修正後に最初にログインしたユーザーへ一度だけ移行します。
   - 移行後は旧共有データを削除し、別ユーザーへ重複して取り込まれないようにします。

4. **動作確認**
   - 異なるメールアドレスが、それぞれ Auth に登録された異なるパスワードでログインできることを確認します。
   - ユーザーAのお気に入りがユーザーBには表示されず、再ログイン後も各自の内容が保持されることを確認します。

## 技術詳細

- `saved_items` は `user_id = auth.uid()` の条件で SELECT / INSERT / UPDATE / DELETE を本人だけに許可します。
- 認証済みユーザーと管理処理に必要な明示的権限を付与し、匿名アクセスは許可しません。
- パスワードはアプリのテーブルやコードには保存せず、Auth の認証情報だけを正とします。
- 既に Auth に設定済みのパスワードは読み出せないため、実際の登録値と異なる既存アカウントだけは管理画面でパスワード再設定が必要です。
